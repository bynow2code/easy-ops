# 脚本列表多选 + 右键批量删除 设计文档

- 日期：2026-09-23
- 状态：已确认（用户批准交互设计与「目录不参与多选」边界）
- 关联：`2026-09-21-nested-tree-sidebar-design.md`（树形侧栏）

## 背景与目标

脚本列表目前只支持单选（单击选中）。批量清理脚本时只能逐条 ⋯ → 删除 → 确认，操作繁琐。目标：

1. 支持 Ctrl/⌘+单击切换选中、Shift+单击范围多选
2. 多选态右键弹「删除」菜单，一次确认批量删除

## 方案对比

| 方案 | 思路 | 结论 |
|------|------|------|
| **A. Sidebar 本地状态 + 循环单删（采纳）** | 多选集合作纯 UI 态放 Sidebar；批量删除 = 循环现有 `script:delete` IPC + 一次 `reload()` | 改动集中在单文件，不动 main/preload/shared；个人级数据量 N 次本地删除毫秒级 |
| B. 多选进 store + 批量 IPC | `selectedScriptIds` 进 zustand，新增 `script:deleteMany` | 多选目前仅侧栏消费，跨组件无需求；动三层 IPC 面过大，YAGNI |
| C. 重构为 antd Tree | 用其自带多选 | 推翻现有自绘树与拖拽实现，动作远超需求 |

## 交互规则

### 多选（仅脚本行；目录不参与）

- **普通单击**：清空多选，仅选中该行（现状不变），详情区页签同步
- **Ctrl/⌘+单击**：切换该行在多选集合中的状态；同时把该行设为 `selectedScriptId`（详情区跟随最后点的那行）；把该行从集合移出后集合为空时，`selectedScriptId` 保持不变（详情区不回空态）
- **Shift+单击**：以「锚点行」到当前行的**树前序范围**整体选中；范围跨目录允许，路过的**目录行不进选区**（选区永远是纯脚本集合）
- 锚点 = 最近一次普通单击或 Ctrl 单击的行（两者都更新锚点）；无锚点时 Shift+单击等价普通单击
- **Esc**：清空多选；**搜索**：进入搜索态或修改关键字时清空多选（搜索态树是剪枝视图，范围选择会错乱）

### 目录行的边界（用户确认）

- **目录不参与多选**：Ctrl/Shift+点目录行 = 忽略修饰键，走普通单击（展开/收起），行为与现状完全一致
- 理由：① 目录删除语义是「子项上移」，与脚本删除（消失）不可组合，混合批量的结果难预判，不可逆操作忌讳此点；② 目录行单击已被展开/收起占用，避免修饰键语义打架；③ 目录批量操作暂无真实场景
- 目录删除仍走目录 ⋯ 菜单（单条 + 专门的上移确认文案），与脚本多选路径互不干扰

### 右键菜单

| 场景 | 行为 |
|------|------|
| 右键**未选中**脚本行 | 先单选该行，弹单条菜单（复制 / 删除），与 ⋯ 菜单同项 |
| 右键已选行且多选数 = 1 | 弹单条菜单（复制 / 删除） |
| 右键已选行且多选数 > 1 | 弹多选菜单，仅一项「删除 N 个脚本」（danger） |
| 右键目录行 | 无右键菜单（目录操作只在 ⋯ 菜单，现状不变） |

### 视觉

- 多选行复用现有灰胶囊选中底色（`.app-row-selected`），不区分主次选中
- 多选态下行的悬停操作钮（执行/编辑/⋯）照常显示，行为单行语义

### 拖拽

- 拖拽不参与多选：拖拽仍是单行语义（拖谁排谁），多选集合不随之变化、不被清空
- 多选行 `draggable` 保持开启，行为与现状一致

## 状态与数据流

```
Sidebar 本地 state:
  selectedIds: Set<string>   // 多选脚本 id 集合(纯 UI 态,不持久化)
  anchorId: string | null    // Shift 范围选择的锚点

渲染: 选中态 = selectedIds ∩ 当前 scripts(脏 id 兜底剔除)
右键: Dropdown 受控 open + onContextMenu 定位,菜单项按场景动态生成
批量删除: 确认框 → 校验 id 仍存在 → Promise.allSettled 循环 scripts.remove
         → 失败>0 报错 → reload()(页签/草稿/详情选中由既有 reload 逻辑收尾) → 清空 selectedIds
```

- 确认框文案：标题「删除脚本」；正文列出前 5 个名字（超出部分「等 N 个脚本」）+「此操作不可撤销」；okText「删除」danger
- 删除前校验：确认框打开期间列表可能已变（其他入口删除），执行前逐 id 校验仍存在，失效 id 跳过；全部失效则提示后不执行
- 部分失败：成功的保留删除结果，失败的留在列表并 message.error；无论成败，多选集合清空（避免半残选区）

## 不做的事（YAGNI）

- 批量复制、批量移动、批量执行
- 目录多选与混合批量删除
- 多选态拖拽批量移动
- 多选持久化（重启清空，纯会话态）

## 测试计划（vitest + testing-library，沿用 aria-label 定位惯例）

1. **选择语义**：Ctrl 单击切换；Shift 范围（跨目录、路过的目录不入选）；普通单击清空；Esc 清空；搜索清空
2. **右键菜单**：右键未选行 = 单条菜单且该行被选中；右键多选行 = 批量菜单（文案含 N）；右键目录行无菜单
3. **批量删除**：确认框文案含数量与名字；确认后逐条调用 remove + 一次 reload；删除前校验失效 id 跳过；部分失败报错且失败项保留、多选清空
4. **边界**：多选含已删脚本时渲染剔除；删除后详情区/页签回退由 reload 兜底
