## Windows 图标显小一圈修复（用户反馈“还是比别的小了一圈”）
- 根因（非规格问题）：上一轮从 `logo-mac.png` 生成 ico，但 `logo-mac.png` 是带 ~9% 透明内边距的“悬浮圆角方块”（实测铺满 67%、边距 9%）；MAC 按整块缩放无妨，Windows 开始菜单/任务栏按整块 256 磁贴缩放，四周留白导致显小一圈。图像规格本身标准（256² + 7 帧多尺寸）。
- 实测对比：`logo-1024.png` 铺满 100%、四角透明（满铺圆角方块）；`logo-mac.png` 铺满 67%、边距 9%。
- 修复：改用满铺源 `logo-1024.png` 经 Pillow 重新生成 `logo.ico`（7 帧 16/24/32/48/64/128/256，32-bit）。逐帧核验 256 帧满铺=True、四角透明=4/4（圆角正常），内边距已消除。
- 记忆更新：MEMORY.md 增“Windows ico 必须满铺源”关键坑说明；Win 仍用 logo.ico（源改 logo-1024.png），Mac 仍用 logo-mac.png（留白无妨）。

## 新功能：脚本可单独指定 Shell 解释器（覆盖全局）
- 需求：脚本可单独选 Shell（从全局 shell 列表选），未设置则跟随全局 shell 配置；列表/输出面板要标记「该脚本单独用了不同的 shell」。
- 数据模型：`scripts.json` 每脚本新增可选字段 `shellId`（null/'' = 跟随全局；非空 = shell 列表里的 id）。
- 服务端 `server/index.js`：
  - POST/PUT `/api/scripts`、`POST /api/scripts/import` 均接收并归一化 `shellId`（空串/undefined/null → null）。
  - 新增 `resolveScriptShell(script)`：脚本 shellId 命中 detectedShells 则用它的，否则回落全局 `shell`。
  - `execute-stream` / `batch-execute-stream` 改用 effectiveShell 执行；无 shell 检查改为「脚本级生效 shell」而非只查全局（脚本单独指定有效 shell 时即便全局无 shell 也能跑）。
  - SSE `start` 事件回传 `shellId`/`shellName`/`isCustomShell`（脚本 shellId 命中即为 true）。
  - 改完跑 `npm run build:server` 重新打包 `server/dist/index.cjs`（运行时加载的是 dist 而非源码，务必同步）。
- 客户端 `client/src/App.jsx` + `App.css`：
  - 挂载时预拉 `/api/shells` 供表单与列表用（原仅在 App Info 弹窗打开时拉）。
  - Add/Edit 表单新增「Shell Interpreter」下拉：默认项「Global default」+ 各 shell。提交带 shellId。
  - 脚本列表名旁：脚本设了 shellId 且能映射到 shell 时显示黄色 `⚙ <shell名>` 徽标（`.shell-override-badge`），提示单独指定。
  - 输出面板头部显示本次实际 shell（`.output-shell-badge`）；`isCustomShell` 时高亮黄底强调。
- 验证：隔离 SCRIPT_DATA_DIR 起 server 做 E2E——POST/GET/PUT/import 的 shellId 持久化正确；execute-stream 的 start 事件正确回传 shell 字段。client 用 esbuild 转译 + `vite build` 均通过（vite 首次因 safe-delete shim 拦截 dist 清理失败，rm -rf dist 后重 build 成功）。
- **列表 Shell 标记样式演进（用户反馈）**：①初版黄底粗体 `⚙ <shell名>` → 用户嫌丑；②改灰底斜体全称 → 用户嫌灰色不好看 + 另起一行浪费空间 + 全称占空间；③**最终版**：恢复黄色好看风格（`var(--bg-state-warning)` 黄底 + warning 边框），但只放一个图标、不显示全称，**与脚本名同一行**（`.script-name-cell` flex 容器，`gap:6px`），鼠标悬停（title）才显示解释器全称。输出面板 badge 已按用户要求移除（仅保留后端 start 事件的 shellName 字段）。**用户偏好：黄色标识比灰色好看。**
- **列表 Shell 标识最终方案**：图标几经调整——`⚙`(黄底粗体全文)→灰底斜体→`🐚`(emoji 太花哨，用户嫌不符合简洁风格)→`>_`(纯文本终端符)→**最终用户提议「右上角小圆点」**：脚本名右上角一个黄色小圆点（类似通知红点但保持黄色）。实现：`.script-name-wrap` 包 `position:relative`，`.shell-override-dot` absolute 定位（`top:-2px;right:-9px`，7px 圆，`var(--text-state-warning)` 黄填充 + `box-shadow:0 0 0 1.5px var(--bg)` 描边跨浅/深主题清晰）。**hover 提示**：用户反馈原生 `title` 提示跑到上方（浏览器控件位置不可控）——改用自定义 CSS tooltip（`.script-name-wrap[data-tip]:hover::after` 气泡 + `::before` 小三角）稳定出现在脚本名**正下方**，并去掉原生 title 避免双重提示。README 同步说明。
