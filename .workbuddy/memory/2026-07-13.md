## Windows 打包图标偏小修复（第三轮）
- 问题：Start 菜单/桌面快捷方式/任务栏中 EasyOps 图标比邻近应用小（如截图比微信小一圈）。
- 第一轮根因：`electron-builder` 从 `logo.png` 自动生成的 `.ico` 只含 256×256 单个尺寸；Windows 取 48/64/128 等尺寸时缩放，视觉偏小。
- 第一轮处理：用 `logo-1024.png` 生成多尺寸 `logo.ico`（16/24/32/48/64/128/256），并把 `build.win.icon` 指向它。
- 第二轮根因：即使尺寸齐全，原 logo 的图形内容也**没有顶满画布**。`logo-1024.png` 的内容 bbox 是 819×819，只占 1024×1024 画布的约 80%；四个角是透明的圆角，Windows 渲染时这些透明角会露出 tile 背景，让图标看上去缩在一个小方块里。
- 第二轮处理：用 `logo-1024.png` 裁掉透明边角，再用背景色 `#1D1D2D` 把画布补满，生成 `client/public/logo-win.ico`（16/24/32/48/64/128/256）；把 `build.win.icon` 从 `client/public/logo.ico` 改为 `client/public/logo-win.ico`。
- 第三轮根因：补满画布时直接用背景色填充四个角，导致任务栏图标变成**直角方块**，而微信等图标是圆角方块。
- 第三轮处理：在 1024×1024 画布上先画一个与微信风格相近的圆角矩形（圆角半径 204px，约 20% 边长），填充为 logo 背景色 `#1D1D2D`，再把原始 logo 叠在上面。这样透明边角不再露 tile 背景，同时整体外形保持圆角。
- 验证：ICO 头解析含 7 张图像；预览图显示新图标顶满画布且四角圆润，与微信任务栏图标风格一致。
- 后续：重新执行 `npm run electron-build` 后生效；Windows 图标应和微信等顶满 tile 且带圆角的应用同尺寸、同风格。

## 修复 Windows 执行脚本弹出 WSL 终端窗口（严重 bug）
- 问题：Windows 版执行脚本时，会调起 Windows 终端（WSL/Windows Terminal，见截图）。
- 根因：
  - 第一轮只加了 `windowsHide: true`，但弹出来的是 **WSL 的 Windows Terminal**，不是传统 cmd 控制台；`windowsHide` 对它无效。
  - 真正原因是 `server/index.js` 里 `spawn(shell.command, [], ...)` 对 WSL bash 或 Git Bash 启动时**没传参数**，bash 默认进入交互式 shell，于是打开 Windows Terminal。
- 处理（最终方案）：
  - 在 `detectShell()` 返回的 `shell` 对象中增加 `args` 字段。
  - 关键升级：**对 WSL 启动器（`System32\bash.exe` 或 `wsl.exe`）改用 `wsl.exe` 作为 command，args 为 `['bash','-s']`**。
    原因：Windows 11 上 WSL 交互式 shell 默认通过 Windows Terminal 启动，即使 `bash.exe -s` 也可能弹窗；
    而 `wsl.exe bash -s` 带命令参数时在后台直接执行，不触发 Windows Terminal。
  - 对 Git Bash 等其他 bash 保持 command 不变，args 为 `['-s']`（非交互式从 stdin 读取，避免 MinTTY）。
  - 对 `cmd.exe` 回退保持 `args: []`（cmd 不支持 stdin 脚本，仅兜底）。
  - 两处 `spawn`（单条执行 index.js:481、批量执行 index.js:584）统一改为 `spawn(shell.command, shell.args, ...)`。
  - 启动时日志新增 `[Shell] Args: [...]` 便于确认。
- 兼容性：`windowsHide: true` 保留；`killChild` 在 Windows 用 `taskkill /pid /T /F` 杀整棵进程树，强制中断不受影响。
- **真正根因（第 N 轮才定位）：`detached: true` 本身**。
  - Windows 上 `spawn` 的 `detached: true` 官方语义就是「给子进程分配全新控制台窗口」（Node 文档：*The child will have its own console window*），与 `windowsHide` 打架，且 wsl.exe 拉起的独立 Windows Terminal 根本不受 `windowsHide` 控制。
  - `detached` 原本只为 POSIX 上 `process.kill(-pid)` 整组杀而设；Windows 的 `killChild` 走 `taskkill /T /F`，本就不需要 detached。
  - 修复：两处 spawn 的 `detached` 改为 `process.platform !== 'win32'`（仅非 Windows 开启），Windows 不再弹窗，POSIX 整组杀不受影响。
- 验证：`node --check server/index.js` 通过。

## 修复 AppInfo 弹窗 Shell 路径只显示 "wsl.exe"
- 问题：用户机器走 WSL 分支时，AppInfo 弹窗 Shell 行只显示 `wsl.exe`，无真实路径。
- 根因：`server/index.js` 的 `detectShell()` 在 `isWslLauncher` 分支里把 `result.fullPath` 写死成 `'wsl.exe'`（与 `command` 相同），导致弹窗（渲染 `systemInfo.shell.fullPath`）只能显示无意义的 `wsl.exe`。数据其实一直返回，CSS 也可见，只是路径值本身没意义。
- 处理：WSL 分支改为 `result.fullPath = fullPath`（保留真实检测到的 bash 启动器路径，如 `C:\Windows\System32\bash.exe`），`command` 仍为 `wsl.exe`、`args: ['bash','-s']`（执行逻辑不变，不弹终端）。
- 验证：`node --check` 通过；用独立脚本模拟 WSL 分支，确认 `display path = C:\Windows\System32\bash.exe`、`executes = wsl.exe bash -s`。

- **重要：用户使用 `npm run electron-dev`（`npm run build && electron .`）而非打包版本**。
  - 该模式下 `electron/main.js` 用 `fork` 直接运行 `server/index.js` 源码，GUI 热重载不会重启 server 进程。
  - 因此每次改 server 后必须**完全停止再重新运行 `npm run electron-dev`** 才能生效（只按刷新/F5 没用）。
  - 注意：此前用户一直报"没改好"，排查发现其 dist-electron 构建是 7/11 的（早于任何修复）；需确保在 electron-dev 下完整重启。


## 修复 npm 警告：Unknown (user/project) config "ELECTRON_MIRROR"/"electron_mirror" 等
- 问题：npm 操作反复报 `npm warn Unknown user config "ELECTRON_MIRROR"` / `"ELECTRON_BUILDER_BINARIES_MIRROR"`（用户级 .npmrc），后又报 `npm warn Unknown project config "electron_mirror"`（项目级 .npmrc）。
- 根因：`ELECTRON_MIRROR`、`ELECTRON_BUILDER_BINARIES_MIRROR`、`electron_mirror` 都不是 npm 的合法配置键，只是 electron / electron-builder 进程读取的**环境变量**。写进任何 `.npmrc` 都会触发 npm 的 unknown-config 警告。
- electron 实际读取顺序（`@electron/get/dist/cjs/artifact-utils.js` `mirrorVar`）：优先 `npm_config_electron_mirror` → 最后一项是 **`ELECTRON_MIRROR` 环境变量**（可直接用环境变量，无需 .npmrc）。electron-builder 的 `binDownload.js` 读 `ELECTRON_BUILDER_BINARIES_MIRROR` 环境变量。
- 处理（最终方案）：
  - 清空项目级 `D:\www\EasyOps\.npmrc`（删除 `electron_mirror` 行），消除 "Unknown project config" 警告。
  - 用户级 `C:\Users\bynow\.npmrc` 只保留合法键：`registry`、`fetch-retries`、`fetch-retry-mintimeout`、`fetch-retry-maxtimeout`。
  - 镜像改为用**用户级环境变量**兜底：`ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`、`ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/`。
- ⚠️ 踩坑：用 **bash 链式 `setx`** 设置含 URL 的环境变量时，引号被 Git Bash 处理错误，导致 `ELECTRON_BUILDER_BINARIES_MIRROR` 被污染为 `...binaries/:\Windows\System32\WindowsPowerShell\v1.0\powershell.EXE`(含控制字符)，会让 electron-builder 下载二进制时拼出错误 URL。
  - 正确做法：用 PowerShell 的 `[Environment]::SetEnvironmentVariable('NAME','VALUE','User')` 写注册表，避免 shell 引号问题。已据此重设修复。
- 注意：`setx` / 注册表修改只在**新开终端**生效；旧的已运行终端仍可能持有旧的（甚至被污染的）环境变量值。重开后执行 `npm run electron-dev` / `electron-build` 才会真正走镜像。
- 验证：`npm config get registry` 输出干净、无任何 unknown-config 警告。
- 机制确认：`@electron/get` 的 `mirrorVar` 读 `npm_config_electron_mirror`；`app-builder-lib/binDownload.js` 读 `ELECTRON_BUILDER_BINARIES_MIRROR` 等环境变量。
- 验证：`npm config get registry` 不再出现该警告。注意 `setx` 仅影响新会话，需重开终端后镜像环境变量才生效。
