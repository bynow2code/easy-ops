- monaco-editor 的 package.json 含 `exports` 字段，会阻断对深层 worker 路径的裸导入；Vite8 用 Rolldown，`?worker` 与 `?url` 导入 `monaco-editor/esm/vs/...` 均报 "failed to resolve"（build 直接失败）。

- 不要再用 ESM `import * as monaco from 'monaco-editor'` + `?worker` 思路（在此项目会构建失败）。
- 构建验证：`vite build` 通过（产物 ~210KB），`dist/monaco/vs/loader.js` 已复制；`public` 静态在 dev 走 `/monaco/vs/...`。

## 🔴 shell 代码提示"三次不生效"根因（重要，复用价值高）

用户连报三次"shell 补全没效果"。前两轮我误判为 CSS 裁剪(fixedOverflowWidgets)与循环依赖，均无效。最终用 **Playwright 真浏览器**加载 dev server 验证，定位真因：

- **真因**：`monaco-editor/editor/editor.api` 只是**裸 API**——它只注册 `FormattingConflicts` 一个编辑器贡献，**不注册 `SuggestController`**（补全浮层 UI + `editor.action.triggerSuggest` 命令）。`registerCompletionItemProvider('shell', ...)` 的数据确实写进了语言注册表，但**没有任何 UI 控制器去查询/显示它**，故浮层永不出现，连 Ctrl+Space 都报 `command 'editor.action.triggerSuggest' not found`。之前为瘦身"只引入 editor.api"恰恰砍掉了补全 UI。
- **修复**：在 `setup.js` 的 `editor.api` 基础上补 `import 'monaco-editor/editor/contrib/suggest/browser/suggestController.js'`（仅补全所需贡献，不引入 editor.main 的 70+ 语言包，体积优化仍保留）。验证：Playwright 实测 provider 被调用、`.suggest-widget.visible` 出现、含 `codicon-symbol-function`/`keyword` 项。
- **调试方法（可复用）**：用 Playwright 加载真实页面，点 Add Script、聚焦 `.monaco-editor`、敲 `ec`、查 `.suggest-widget` 是否出现，并 `page.on('console')`/`pageerror` 抓报错；把 editor 实例临时挂 `window.__editor` 可读 `getModel().getLanguageId()`、确认语言与 provider 注册。比反复改 CSS/import 猜要快得多。
- **教训**：Monaco 在 Vite ESM 下，`editor.api` ≠ "完整编辑器"。凡用到 suggest/find/folding 等编辑器功能，必须引入对应 `contrib/*` 模块或 `editor.main`。mock 单测只能验证逻辑，不能证明真实注册/UI 生效——端到端要用真浏览器验。

- 背景排查：此前执行是**单向**——进程输出能渲染到 xterm，但用户按键从未发回进程。后端/IPC 输入管道本已齐全（`ptyClient.write`→`pty:write`→`pty-host.write`→`term.write`），唯独 `client/src/components/ExecutionCard.jsx` 只订阅 `ptyClient.onData` 渲染输出，从未把 xterm 的 `term.onData` 反向发回 pty（全局 grep `term.onData`/`ptyClient.write` 0 处调用）。故交互脚本（read/REPL/ssh/密码提示等）会卡死，非交互脚本（ls）不受影响。
- 改动 `ExecutionCard.jsx`（仅前端，后端/IPC/ptyClient 零改动）：
  - xterm 生命周期内新增 `const offInput = term.onData((d) => { if (sessionIdRef.current) ptyClient.write(sessionIdRef.current, d); })`（sessionId 用 ref 读最新值，Re-run 后 session 变化但本 effect 不重挂载，故必须读 ref）。
  - 新增点击聚焦：`termRef.current` 上挂 `click` 监听调 `term.focus()`（xterm 默认不自动聚焦，否则点不进终端收不到键盘）。
  - cleanup 同步 `offInput.dispose()` + `removeEventListener('click', focusTerm)`。
- 验证：eslint 单文件 0 problems。

## Windows 默认 shell：自动探测（Git Bash 优先）+ 兜底 Git Bash（2026-08-02）

- 改动 `server/shell-detect.js`：
  - 新增模块级 `WIN_DEFAULT_PRIORITY = ['C:\\Program Files\\Git\\bin\\bash.exe', 'C:\\Program Files (x86)\\Git\\bin\\bash.exe', 'C:\\Windows\\System32\\wsl.exe']`（仅 POSIX 受支持项，Git Bash > WSL）。

- 三段行为（node 模拟 win32 + stub fs.accessSync 验证）：仅装 WSL → 用 WSL；Git Bash+WSL 都装 → 优先 Git Bash；都未装 → 兜底 Git Bash 常量。

## 终端/脚本退出全链路核查 + 补缺口（2026-08-02 深夜）
- 用户核验：close / close all / stop / 退出程序 / 重新执行 是否都能正确退出、有无未覆盖场景。结论：原实现**大部分覆盖，但有两个真实缺口**：
  1. **退出程序不清场（最严重）**：`app.on('window-all-closed')` 只 `app.quit()`，主进程从不 kill PTY 会话 → 程序退出后 shell 子进程（及其拉起的脚本/ssh/tail）在 Unix 被 reparent 到 init 成孤儿进程后台继续跑。
  2. **开会话窗口期漏杀**：`handleClose/handleCloseAll/handleStop/handleRerun` 原条件 `exec.mode==='pty' && exec.sessionId` 强依赖渲染层本地 `sessionId`；但 `openSession` 在主进程**同步**注册 `execId→sessionId`，IPC 返回前本地 sessionId 是 `null` → 此窗口内点 close/stop 会漏杀（主进程已注册却没杀）。
- 修复：
  - `electron/pty-host.js` 新增 `killAll()`：遍历 `sessions` 逐个 `killSession`（复用跨平台 kill），清空两张 map，返回杀了几个。
  - `electron/main.js` 加 `app.on('before-quit', () => ptyHost.killAll())`——覆盖 ⌘Q / 菜单 Exit / window-all-closed→app.quit / 直接 app.quit 全部退出路径（Unix 同步发 SIGTERM 给进程组，已足够终止树）。
  - `client/src/App.jsx` 四个 handler 改为「只要 `exec.mode==='pty'` 就 `ptyClient.kill(execId)`」（去掉 `&& sessionId`）；`killByExec` 找不到是无害 no-op，已自然结束的卡也不受影响；open-pending 窗口期现在也能精确杀主进程那一条已注册会话。
  - 已退出但本地仍显示 running 的卡：自然退出时 openSession.onExit 已 `sessions.delete`+`execToSession.delete`，killByExec 找不到→no-op，安全。
  - mock 模式（无 Electron / No Shell 模式）由卡片卸载 effect 清理定时器，无进程泄漏，无需改。
- 验证：lint 0、test 38/38、format 绿、build 成功（仅 monaco chunk 体积告警，预期内）。
