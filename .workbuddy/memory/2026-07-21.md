## 新功能:App Info 弹窗支持切换/持久化 Shell
- 需求:App Info 弹窗原只显示当前在用 Shell 路径;现增加「列出本机所有受支持 Shell + 路径,一键切换,后续脚本执行在该 Shell 上进行,切换持久化」。

### 服务端改动(`server/index.js`)
- 删旧 `detectShell()`(只挑最优一个),新增 `detectAllShells()` 列出全部已安装 Shell(见下方「⚠️ 仅 bash 系」更正)。
  - **⚠️ 经用户纠正:本软件只跑 bash 脚本(spawn 把 `script.content` 经 stdin 喂给 Shell,args 用 `-s`/`bash -s`;自身报错即写「WSL or Git Bash is required to run bash scripts」)。故仅探测 bash 系:**
  - POSIX: **仅 `bash`**(删掉了原先误加的 zsh/sh/fish——非 bash 解释器无法保证兼容下发的 bash 脚本)。
  - Windows: **仅 `wsl.exe`(bash) 与 Git Bash**(删掉了原先误加的 pwsh/powershell.exe/cmd.exe——均非 bash,跑不了 bash 脚本)。
  - 每个描述符含 `{ id, type, name, command, fullPath, args, version }`;用 `which`/`where`/`fs.existsSync` 探测(毫秒级,不实际启动 Shell,避免 WSL 冷启动超时);版本取首行,失败留空。
- 新增持久化:`SHELL_CONFIG_PATH = path.join(SCRIPT_DATA_DIR,'shell-config.json')`,`loadShellConfig()/saveShellConfig()` 只存 `{ selectedId }`(路径每次启动重探测,避免卸载后残留无效绝对路径)。
- 有效 Shell:`resolveEffectiveShell()` = 持久化选中(仍可用)优先,否则 `pickDefaultShell()`(POSIX→bash;Windows→优先 wsl 其次 gitbash,都没有则降级「无 Shell」,**不**自动选 cmd/pwsh,保持旧行为)。全局 `shell` = 有效 Shell,spawn 处直接读它。
- 新增端点:
  - `GET /api/shells` → `{ shells, current, selectedId }`
  - `POST /api/shells/select`(body `{id}`)→ 校验存在、写盘、立即更新全局 `shell` 使其后续 spawn 生效,返回更新后状态。

## 复用的测试经验(路径坑)
- Windows 上 Git Bash 的 `/d/foo` = `D:\foo`;而 Node(Windows) 的 `/d/foo` = `D:\d\foo`(前导 `/` 视作当前盘根)。混用两者做临时目录会找不到文件。统一用带盘符的 `D:/foo` 形式可规避。

## 新功能:手动添加自定义 bash 路径(自动探测扫不到的 bash)
- 需求:有些 bash 装在非标准路径自动扫不到;允许用户手填路径,选择后自动识别是否为 bash,不是则提示「不能使用/不能添加」。
- 服务端(`server/index.js`):
  - `validateBashPath(path)`:去引号→文件存在性检查(命令名跳过)→跑 `"<path>" --version`,输出含 `bash` 才 `{ok:true,version}`;否则识别 zsh/fish/PowerShell 等并返回 `{ok:false,reason}`。
  - `buildCustomShell(path)`:校验通过则构造 `{id:'custom:<path>', type:'bash', name:'Custom Bash', command/fullPath:path, args:['-s'], version, custom:true}`,失败返回 null。
  - 配置扩展:`shell-config.json` 新增 `customPaths:[]`;`buildDetectedShells()` = 自动探测 + 自定义(每次重校验、去重、剔除失效);`detectedShells` 改由它产出。select 端点改 `{...shellConfig, selectedId}` 以**保留** customPaths。
  - 新端点:`POST /api/shells/add`(校验→持久化→重建列表,不支持返回 400+reason)、`POST /api/shells/remove`(仅允许 `custom:true` 项;若移除的是选中项则清 selectedId 并 `resolveEffectiveShell()` 回落)。
- 前端(`client/src/App.jsx`+`App.css`):Shells 列表下加输入框+Add(回车提交),失败回显后端 reason(`.shell-add-error`);自定义项右侧多一个红色 Remove 按钮;新增 `handleAddShell/handleRemoveShell` 与状态 `newShellPath/addingShell/addShellError/removingShellId`。顺手修了旧 CSS 无效色值 `#b7eb8`→`#b7eb8b`。
- 验证:`node -c`+`build:server`+client build 全过;冒烟 8 例全绿(有效 PortableGit bash 识别 GNU bash 5.3.9;node.exe→400「识别为 v22.22.2…不是 bash」;不存在→400「文件不存在」;去重;select 自定义;remove 后回落 wsl+清 selectedId;remove 非 custom→400);持久化重启后 fresh boot 仍列出并重校验。临时目录已清理。

## 🐛 修复:选 GUI 安装包点 Add 会真的把安装程序打开

  - 其余情况改用 `execFileSync(p, ['--version'], { windowsHide:true, timeout:4000, killSignal:'SIGKILL' })`(不走 shell,无命令注入;超时强杀兜底)。

## 🐛 修复:关闭无 Shell 模式时 active shell 不动态刷新
