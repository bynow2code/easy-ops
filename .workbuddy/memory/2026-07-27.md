## BUG 修复：批量删除误报「删除失败」
- 现象：勾选脚本点 Delete Selected 批量删除，弹出 "Failed to delete selected scripts"。
- 根因：`server/index.js` 中 `DELETE /api/scripts/:id`（单条删除）注册在 `DELETE /api/scripts/batch` 之前。Express 按注册顺序匹配，`/api/scripts/batch` 的 `batch` 被 `:id` 捕获，命中单条删除逻辑；找不到 id="batch" 的脚本 → 404 {error:'Script not found'} → 客户端 catch 走到 alert('Failed to delete selected scripts')。
- 本质：路由顺序冲突（静态路径 /batch 应优先于参数路径 /:id）。
- 修复：将 `app.delete('/api/scripts/batch', ...)` 移到 `app.delete('/api/scripts/:id', ...)` 之前，并在注释里标注此约束。express.json 对 DELETE body 解析正常（curl + axios 实测均 OK）。
- 验证：起独立服务（SCRIPT_DATA_DIR 指向临时目录）+ 用 axios 复刻客户端调用 `axios.delete(url,{data:{ids}})` → 返回 200 {success:true,deleted:2}，列表正确清空；单条删除仍正常。测试后已停服并清理临时文件。

## BUG 修复：批量执行时 Execution Outputs 窗口顺序与脚本列表不一致
- 现象：勾选多个脚本「Execute Selected」后，右侧输出窗口顺序 ≠ 左侧脚本列表顺序。
- 根因：`client/src/App.jsx` 渲染端按 `timestamp` 倒序排输出面板（最新执行在最前）；而 `handleBatchExecute` 给每个脚本赋的时间戳是 `batchTimestamp - index`，`index` 是其在 `selectedIds`（勾选顺序）中的位置。因此窗口顺序跟着「勾选顺序」走，与脚本列表顺序不同。
- 修复：改为按脚本在 `scripts` 列表中的顺序（list order）赋递减时间戳（`batchTimestamp - listIndex`），倒序后即 = 脚本列表顺序。单独执行仍用 `Date.now()`（时间戳更大），保持「单独执行排到批量组之上」的既有行为不变。渲染端排序逻辑（按 timestamp 倒序）与注释同步更新。
- 验证：esbuild 转译 App.jsx 通过（exit 0）。
