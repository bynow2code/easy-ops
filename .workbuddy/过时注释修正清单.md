## 已修正（共 6 处，仅改注释、未动代码逻辑）

### 1. client/src/App.jsx（第 317 行附近）
- **问题**：注释称「请求通知权限」，但 `sendCompletionNotification` 从未调用 `Notification.requestPermission()`；Electron 走主进程注入的原生通知本就无需网页权限，浏览器降级分支也依赖「此前已授权」状态。
- **修正**：删除「请求通知权限」描述，改为如实说明两条路径（主进程原生通知 / 浏览器 Web Notification 且本函数不主动申请权限）。

### 2. server/index.js（第 357、585、642 行）
- **问题**：三处「🧪 无 Shell 模式（测试用）」仍标为测试专用，但该模式已是 README 记载的、用户可在 App Info 手动开关的功能，且存在真实的 `POST /api/shells/no-shell-mode` 接口。
- **修正**：去掉「测试用」，改为「可在 App Info 中手动开关」的用户功能定位。

### 3. server/index.js（第 17 行）
- **问题**：注释「Electron 打包后使用用户数据目录，避免写入只读安装目录」是无条件表述，与文件上方 PORT_FILE 注释（「不能写 __dirname」）形成矛盾观感——数据文件在 `SCRIPT_DATA_DIR` 未设置时仍会回退 `__dirname`。
- **修正**：补全回退前提，说明仅在变量未设置（本地独立运行 server）时才回退 `__dirname`，且只适用于开发环境。

### 4. server/index.js（第 8 行）
- **问题**：`const DEFAULT_PORT = 3001;` 与下方端口策略注释「不再使用 3001 区间、改由 OS 分配」自相矛盾，易让人误以为默认监听端口是 3001（实际上 `requestedPort` 来自 `PORT=0`，3001 只是 `serverPort` 初始占位）。
- **修正**：加注释说明它仅为 `serverPort` 初始占位值，真实端口由 OS 分配，实际从不监听 3001。
